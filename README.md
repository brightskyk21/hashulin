# ⭐ 하슐랭 (Hashulin)

> 하진의 미슐랭. 가는 맛집마다 점수 매기는 우리만의 지도.

네이버 지도에서 가게를 검색해 **북마크**하고, 1.0~10.0 점수와 한 줄 평을 기록하는 페이지.
여러 명이 같은 가게에 점수를 매기면 지도 마커에 **평균 점수**가 색으로 표시됩니다.

## 구조

```
브라우저(index.html + 네이버 지도)
  → /api/search   : 네이버 지역검색 API 프록시 (가게 검색)
  → /api/places   : 가게 저장/목록 (Supabase)
  → /api/.../reviews : 점수·평가 저장 (Supabase)
서버: Express (server.js)  ·  저장소: Supabase(PostgreSQL)  ·  호스팅: Render
```

## 1. 키 발급 (3종류)

| 용도 | 발급처 | 환경변수 |
|------|--------|----------|
| 지도 표시 | [네이버 클라우드 플랫폼](https://www.ncloud.com) → Maps → Application 등록 (Web Dynamic Map) | `NAVER_MAP_CLIENT_ID` |
| 가게 검색 | [네이버 Developers](https://developers.naver.com) → 애플리케이션 등록 → **검색 API** | `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET` |
| 저장소 | [Supabase](https://supabase.com) → 프로젝트 → Settings → API | `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` |

> 지도 Application 등록 시 **Web 서비스 URL**에 `http://localhost:3000` 과 배포될 Render 주소(`https://xxx.onrender.com`)를 모두 등록해야 지도가 뜹니다.

## 2. Supabase 테이블 만들기

Supabase 대시보드 → SQL Editor → [`db/schema.sql`](db/schema.sql) 내용을 붙여넣고 Run.

## 3. 로컬 실행

```bash
cp .env.example .env      # 값 채우기
npm install
npm run dev               # http://localhost:3000
```

## 4. Render 배포

1. 이 폴더를 **개인 GitHub 계정**의 새 저장소로 push
2. [Render](https://render.com) → New → **Web Service** → 그 저장소 선택
3. 설정:
   - Build Command: `npm install`
   - Start Command: `npm start`
4. **Environment** 탭에 `.env`의 키들을 그대로 등록 (`PORT`는 생략 — Render가 자동 주입)
5. 배포된 주소를 네이버 지도 Application의 서비스 URL에 추가

## 참고
- 네이버 지역검색 API는 **결과 최대 5건**입니다. 정확한 가게 이름으로 검색하세요.
- 마커 색: 빨강(낮음) → 초록(높음), 회색은 평가 없음.

## V2 개발 상태 (2026-10-10)

`/v2/`에서 카카오 로그인, 이름 저장, 모임 생성/전환, 일회용 초대 링크,
방문별 본인 점수·감상 저장/수정, 멤버별 필터, 평균 점수를 사용할 수 있습니다.

장소 이름·주소·날짜가 동일한 새 기록도 같은 방문으로 합쳐집니다.
기존 리뷰 87개와 장소 사진 47장을 연결했습니다. 이전 작성자는 모임장이 계정을 지정하고 당사자가 확인하면 본인 리뷰만 수정할 수 있습니다. 민혁 리뷰 42개는 사용자 확인 후 연결됐으며, 하진 리뷰 45개는 가입 후 연결합니다. 지도·갤러리·일정은 V2에 연결했습니다. 네이버 허용 주소에 localhost:4174를 추가하여 배경 지도와 점수 마커 표시까지 확인했습니다.

- 카카오 앱 Redirect URI: `https://edzagjjwfoqqlgptljlw.supabase.co/auth/v1/callback`

- 서버 환경변수: `SUPABASE_PUBLISHABLE_KEY` (관리자 키 사용 금지)

`npm install` 후 `PORT=4174 npm start`로 실행합니다. 프리텐다드는 버전을 고정한 CDN을 사용합니다.

공식 설정 문서: https://supabase.com/docs/guides/auth/social-login/auth-kakao

## 배포 전 확인 (2026-10-10 종합 점검)

현재 코드는 배포 보류 상태입니다. 새 화면의 원본 리뷰/사진 조회와 확인된 작성자 본인 수정은 연결됐지만,
V2의 지도/갤러리/일정 연동과 별개로 기존 홈페이지에서 V2로의 운영 전환은 아직 끝나지 않았습니다.
서버의 레거시 API 보호 코드는 이 연결이 없으면 접근/수정을 차단합니다. 지금 main에 푸시하면
Render의 On Commit 설정으로 기존 화면이 깨질 수 있으므로 전환 조건을 먼저 충족해야 합니다.

- `/healthz`: Render용 상태 확인 경로
- `LEGACY_GROUP_ID`: 원본 기록에 접근 가능한 명시적 모임 ID
- `003_invites_and_permissions.sql`, `004_legacy_archive.sql`: 적용 완료
- `.github/workflows/test.yml`: GitHub에서 npm ci + npm test
- 자세한 검증/남은 조건: `db/migrations/README.md`

## V2 지도·갤러리·일정

- Node 22 이상, 설치는 잠금 파일을 사용하는 `npm ci` 권장.
- 장소별 기존/새 평가를 함께 표시하고 지도 검색·저장·방문 기록을 연결합니다.
- 사진은 `group-photos` 비공개 버킷에 저장합니다. 서버만 업로드/서명하고, 사용자 JWT의 모임 권한을 확인한 뒤 5분 URL을 발급합니다. 버킷에 공개 읽기 정책을 추가하지 마세요.
- 업로드: JPG/PNG/WebP, 파일당 8MB·최대 10장. 서버에서 실제 이미지 검사, 40MP 제한, 회전/최대 2400px 변환, EXIF 제거. HEIC는 JPG 변환 필요.
- 사진 설명/휴지통/복원은 업로더 또는 모임장만 가능합니다. 과거 사진은 원래 업로더를 추측하지 않고 모임장이 관리합니다.
- 일정은 모임 멤버가 공동 편집하고 취소/복원이 가능합니다. 버전 충돌은 409로 거부하며 이전 값은 감사 테이블에 보관합니다.
- 기존 `photos` 공개 버킷은 현재 Render 호환을 위해 유지 중입니다. 운영 전환 완료 전까지 모든 과거 사진이 비공개라고 안내하면 안 됩니다.
- 장소/일정 복사 SQL과 별도로 기존 사진 바이트의 백업·변환·해시 검증을 수행했습니다. 원본 테이블 7개는 백업과 동일함을 재확인했습니다.

## 모임 권한 회수와 리뷰 충돌 방지 (2026-10-10)

- 모임 관리에서 본인 탈퇴 또는 모임장의 멤버 내보내기를 지원합니다. 모임장 본인 탈퇴는 막고, 기존 기록과 작성자 연결은 보존합니다.
- 탈퇴/내보내기는 미사용 초대를 취소합니다. 재가입에는 새 초대가 필요합니다. 열린 화면은 30초 주기 및 다시 활성화할 때 멤버십을 확인합니다. 발급된 사진 URL은 최대 5분 유지됩니다.
- 새 리뷰에 버전과 변경 이력을 적용했습니다. 다른 기기에서 먼저 저장했다면 409로 거부하고 작성 중 내용을 유지합니다. 최신 평가를 다시 불러올 수 있으며, 옛 RPC와 방문 재등록으로도 다른 내용을 덮어쓸 수 없습니다.
- 업로드 완료는 서버 전용 RPC에서 멤버십 확인과 메타데이터 삽입을 한 트랜잭션으로 처리합니다.
- Node 테스트 6개와 PGlite 001–007 권한 검사를 통과했습니다. 실제 두 계정/두 기기 검증은 남아 있으며 Git/Render 배포는 하지 않았습니다.
